# Календарь самогонщика — план проекта

Android-приложение на Flutter: рецепты, партии, календарь процессов (брага → перегон → настойка → выдержка), учёт тары и дегустаций.

Статус: **этап планирования**, кода ещё нет. Документ — рабочая база, по нему режем объём на MVP.

## 1. Идея и позиционирование

Приложение не «ещё один справочник рецептов», а **журнал процессов с календарём**: ты заводишь партию по рецепту, приложение само раскладывает её на события (поставить брагу → проверить плотность → снять с осадка → перегон → залить в бочку → первая дегустация → готово к розливу) и напоминает, что делать сегодня.

Три вещи, которых нет у существующих решений (Broover, StillLog, Brewfather — все англоязычные и/или заточены под пиво):

1. **Русский язык и русская школа** — сахарная брага, КОДИ/ГМ, спирт-сырец, «головы/тело/хвосты», настойки и наливки (хреновуха, клюквовка, кедровка), щепа вместо бочки. Терминология та, которой реально пользуются.
2. **Календарь как главный экран**, а не журнал задним числом. Напоминания: «взболтать настойку», «долить бочку», «снять с осадка», «дегустация через месяц».
3. **Связка с собственной колонной** — у нас есть Smart-Column-S3 с HTTP API (`/api/history`, `/api/process/*`, `/api/settings/fermentation`): приложение может подтягивать реальные перегонки и температуру брожения, а не требовать ручного ввода.

## 2. Что хранит приложение (сущности)

- **Рецепт** — шаблон: тип (брага / дистиллят / настойка / ликёр / выдержка / джин / ректификация), состав, шаги с длительностями и температурами, ожидаемый выход, источник (книга, форум, свой).
- **Партия (batch)** — конкретное воплощение рецепта: дата старта, объём, ёмкость, статус, родительская партия (брага → спирт-сырец → сортировка → настойка). Цепочка «от сахара до бутылки» прослеживается целиком.
- **Событие** — плановая или фактическая точка процесса, основа календаря и напоминаний.
- **Замер** — плотность/сахар/Brix, температура, крепость, кислотность, pH. Строит график брожения и «когда уже готово».
- **Перегонка** — прогон с фракциями: голова/тело/хвост, объём и крепость каждой банки, температура в кубе, скорость отбора.
- **Ёмкость/тара** — бочка (объём, обжиг, степень обугливания), бутыль, нерж, банка, бутылка. Кто в ней стоит и сколько.
- **Выдержка** — партия в бочке/на щепе: дата закладки, план, доливки, расчёт ангельской доли, график дегустаций.
- **Дегустация** — оценка, аромат/вкус/послевкусие, что менять в следующий раз, фото.
- **Оборудование** — аппарат (пот-стилл, колонна, НБК), куб, мощность, датчики, адрес Smart-Column-S3.
- **Ингредиент** — справочник: сахар, солод, ферменты, дрожжи, специи, ягоды, с их нормами расхода.

Подробная схема — `docs/DATA_MODEL.md`.

## 3. Экраны (обзор)

Нижняя навигация из 5 пунктов:

1. **Сегодня** — задачи на сегодня и просроченные, активные партии с прогрессом, «скоро готово».
2. **Календарь** — месяц/неделя/список, фильтры по типу процесса, цветовые метки.
3. **Партии** — список с фильтрами по статусу, поиск, быстрый старт новой партии.
4. **Рецепты** — каталог встроенных + свои, поиск, избранное, масштабирование под свой объём.
5. **Ещё** — калькуляторы, склад/погреб, дегустации, оборудование, справочник, настройки.

Детально с состояниями — `docs/UX.md`.

## 4. Технический стек

Проверено на этой машине (19.11.2026):

| Компонент | Статус |
|---|---|
| Android Studio 2025.2.2 + JBR 21 | установлено |
| Android SDK: platforms 33/34/36, build-tools 34.0.0/36.1.0, platform-tools, NDK, cmake | установлено |
| Эмулятор `Medium_Phone_API_36.1` | создан, работает |
| JDK 21 (через Android Studio) | есть; системный `java` — 1.8, для Gradle не годится, используем JBR |
| **Flutter SDK** | **отсутствует** (в PATH висит мёртвый `C:\flutter`) — ставим 3.50.0 stable / Dart 3.14 |
| `cmdline-tools` | нет, понадобится для `sdkmanager`/лицензий (можно поставить отдельно) |

Предполагаемые зависимости:

- **БД**: `drift` (SQLite, реактивные запросы, миграции, типизированный SQL) — важнее `sqflite`, потому что календарь и списки реактивны.
- **Состояние**: `riverpod` + `go_router`.
- **Уведомления**: `flutter_local_notifications` + `timezone`, точные будильники, канал «напоминания о процессах».
- **Календарь**: `table_calendar` (или своя сетка, если упрёмся в кастомизацию).
- **Графики**: `fl_chart` (кривая брожения, кривая перегонки).
- **Прочее**: `intl` (локализация RU, формат дат), `share_plus` + `file_picker` (бэкап/экспорт), `image_picker` (фото дегустаций), `http`/`dio` (Smart-Column-S3).
- **Сборка**: `flutter build apk --release` + подпись; в перспективе GitHub Actions.

Принципы: **оффлайн-первый** (всё локально, без аккаунта), данные экспортируются в JSON/CSV, никакой телеметрии.

## 6. Риски и ограничения

- **Сторы и алкогольная тематика**: Google Play и RuStore по-разному смотрят на контент про домашнее производство алкоголя — возрастной рейтинг 18+, формулировки «рецепты для домашнего приготовления», без призывов к продаже. Проверить правила до публикации; для личного пользования вопрос снимается (ставим APK напрямую).
- **Точные будильники на Android 13+** требуют разрешения `SCHEDULE_EXACT_ALARM` и объяснения пользователю; иначе напоминания «плывут» — делаем fallback на неточные + бейдж в приложении.
- **Данные пользователя**: рецепты и журнал — это годы записей, поэтому бэкап обязателен с первого релиза, а не «потом».
- **Объём контента** — самая дорогая часть: 100+ рецептов и справочников надо не выдумать, а собрать и вычитать. В MVP берём проверенный минимум, остальное — пачками.
