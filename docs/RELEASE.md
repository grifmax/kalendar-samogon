# Выпуск в магазины

Решено: приложение публикуется в **RuStore, Google Play и App Store**. Значит, требования площадок учитываем с первого этапа, а не в конце.

## Что нужно иметь к моменту подачи

### Общее

- [x] Иконка приложения: `app/design/icon-source.png` → `python tools/make_icon.py` собирает 512×512 мастер, adaptive icon Android и `AppIcon.appiconset` iOS.
- [x] Сплэш-экран: Android 12+ через `windowSplashScreen*`, до 12 — `launch_background`, iOS — `LaunchScreen.storyboard`; название выводит экран Flutter под заставкой.
- [x] Скрипт съёмки скриншотов: `app/tools/make_screenshots.ps1` (снимает с запущенного эмулятора в `dist/screenshots`). Кадры нужно проверить глазами перед загрузкой.
- [x] Описание: короткое, полное, «что нового», ключевые слова — `docs/STORE_LISTING.md`.
- [x] Политика конфиденциальности — `docs/PRIVACY.md`. Осталось опубликовать по публичному URL (GitHub Pages / Notion) и вставить ссылку в карточку.
- [x] Возрастной рейтинг: 18+ (RuStore — прямая маркировка, Google Play — анкета IARC, App Store — 17+). Ответы на анкету IARC расписаны в `docs/STORE_LISTING.md`.
- [ ] Заявление об отсутствии рекламы и покупок (если так и будет — это плюс для модерации).
- [ ] Проверка формулировок: «рецепты для домашнего приготовления», «журнал процессов», без призывов к продаже и без инструкций по обходу закона.

### Android

- [x] Релизный keystore: `app/android/upload-keystore.jks` (RSA 2048, срок 10000 дней, alias `upload`).
- [x] `app/android/key.properties` (в `.gitignore`) с путём и паролями; `build.gradle.kts` читает его в `signingConfigs.release`. Если файла нет — сборка откатывается на debug-подпись, чтобы `flutter run --release` работал в чистом клоне.
  - **Важно:** keystore в формате PKCS12 (по умолчанию в JDK 9+) не хранит отдельный пароль ключа. `keyPassword` обязан совпадать с `storePassword`, иначе `signReleaseBundle` падает с `Given final block not properly padded`.
- [ ] `applicationId` — `ru.distiller.kalendar_samogon`, менять после публикации нельзя.
- [x] `flutter build appbundle --release` → `.aab` для Google Play.
- [x] `flutter build apk --release` → `.apk` для RuStore и прямой установки.
- [ ] `versionCode` растёт с каждым релизом (в `pubspec.yaml` — `version: X.Y.Z+N`).
- [ ] Проверить `flutter build appbundle` на отсутствие debug-подписи: `apksigner verify --print-certs`.

### iOS (нужен macOS или CI с macOS-раннером)

- [ ] Apple Developer Program ($99/год), App ID `ru.distiller.kalendarSamogon`.
- [ ] `flutter build ipa --release` на Mac; подпись через Xcode или `--export-options-plist`.
- [ ] TestFlight-сборка, затем ревью в App Store.
- [ ] Учесть: Apple строже всех к алкогольной тематике. Запасной путь — Android-платформы, iOS позже.

## Порядок действий

1. [x] Сгенерировать keystore, положить `key.properties`, настроить `signingConfigs`. **Ключ и пароли — в надёжное место, потеря = невозможность обновлять приложение в Google Play.** Сделайте копию `app/android/upload-keystore.jks` и `key.properties` в менеджер паролей и на отдельный носитель.
2. [x] Сделать иконку и сплэш, заменить дефолтные `ic_launcher`.
3. [ ] Собрать `.aab`, проверить подпись, загрузить в Google Play Console (внутреннее тестирование).
4. Собрать `.apk`, загрузить в RuStore (консоль разработчика).
5. Заполнить карточки: описание, скриншоты, категория («Образ жизни» / «Еда и напитки»), рейтинг 18+.
6. Дождаться ревью, исправить замечания (типичные: «пропаганда алкоголя» — снять формулировками, «нет политики конфиденциальности» — добавить ссылку).
7. iOS: после появления Mac/CI — TestFlight, потом App Store.

## Версионирование

- `VERSION` в корне — источник правды для документации и CHANGELOG.
- `pubspec.yaml` → `version: X.Y.Z+N`, где `N` — `versionCode`/`build number`. Оба должны совпадать с `VERSION` по X.Y.Z.
- Правило: перед каждой сборкой на публикацию — поднять `N`.

## Автоматизация (когда появится CI)

- GitHub Actions: `flutter analyze`, `flutter test`, `flutter build appbundle` на каждый пуш в `main`.
- Отдельный workflow для iOS: macOS-раннер, `flutter build ios --no-codesign`, проверка что код собирается под iOS.
- Секреты keystore — в GitHub Secrets, не в репозитории.

## Что проверено по правилам площадок (21.11.2026)

**Google Play — Tobacco and Alcohol.** Запрещено: помогать продаже алкоголя,
поощрять незаконное или неуместное употребление, показывать алкоголь
несовершеннолетним, изображать чрезмерное употребление положительно. Приложение
под это не попадает: продажи нет, призывов нет, журнал процессов. Обязателен
контент-рейтинг IARC — без него приложение не опубликуют; ответы на анкету в
`docs/STORE_LISTING.md`.

**RuStore.** Возрастные рейтинги: 18+ — «высокий уровень насилия, сексуальный
контент, упоминания наркотиков или алкоголя». Алкогольная тематика не запрещена,
но подпадает под «особые условия размещения» — нужен корректный рейтинг 18+ и
нейтральные формулировки без призывов.

**App Store.** Самые строгие; алкогольные приложения регулярно отклоняют.
Стратегия: iOS собираем, но релиз не блокирует Android-площадки.

Общий принцип формулировок: приложение — **журнал и планировщик**, а не
руководство по употреблению.

## Риски модерации

| Площадка | Отношение к тематике | Что делать |
|---|---|---|
| RuStore | лояльно к русскоязычным приложениям про хобби | рейтинг 18+, нейтральные формулировки |
| Google Play | политика по алкоголю: нельзя поощрять чрезмерное употребление и продажу | без продажи, без «как пить», акцент на учёт и рецепты |
| App Store | самые строгие; алкогольные приложения часто отклоняют | закладываем, но не блокируемся: iOS — второй приоритет |

Общий принцип: приложение — **журнал и планировщик**, а не руководство по употреблению. Это же и в описании в сторе.
