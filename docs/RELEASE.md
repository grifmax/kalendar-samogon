# Выпуск в магазины

Решено: приложение публикуется в **RuStore, Google Play и App Store**. Значит, требования площадок учитываем с первого этапа, а не в конце.

## Что нужно иметь к моменту подачи

### Общее

- [ ] Иконка приложения (512×512 PNG для сторов, адаптивная иконка Android, AppIcon для iOS).
- [ ] Сплэш-экран (Android 12+ использует системный splash API).
- [ ] Скриншоты: минимум 4 на телефон, 2–3 на планшет; для iOS — отдельные размеры.
- [ ] Описание: короткое (80 символов), полное (до 4000), что нового.
- [ ] Политика конфиденциальности по публичному URL. Формулировка: приложение не собирает и не передаёт персональные данные, всё хранится на устройстве, интернет используется только для связи с колонной (после M4).
- [ ] Возрастной рейтинг: 18+ (алкогольная тематика). В RuStore — соответствующая маркировка, в Google Play — IARC-анкета, в App Store — возрастная категория 17+/18+.
- [ ] Заявление об отсутствии рекламы и покупок (если так и будет — это плюс для модерации).
- [ ] Проверка формулировок: «рецепты для домашнего приготовления», «журнал процессов», без призывов к продаже и без инструкций по обходу закона.

### Android

- [ ] Релизный keystore: `keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`.
- [ ] `android/key.properties` (в `.gitignore`!) с путём и паролями; чтение из `build.gradle.kts` в `signingConfigs`.
- [ ] `applicationId` — `ru.distiller.kalendar_samogon`, менять после публикации нельзя.
- [ ] `flutter build appbundle --release` → `.aab` для Google Play.
- [ ] `flutter build apk --release` → `.apk` для RuStore и прямой установки.
- [ ] `versionCode` растёт с каждым релизом (в `pubspec.yaml` — `version: X.Y.Z+N`).
- [ ] Проверить `flutter build appbundle` на отсутствие debug-подписи: `apksigner verify --print-certs`.

### iOS (нужен macOS или CI с macOS-раннером)

- [ ] Apple Developer Program ($99/год), App ID `ru.distiller.kalendarSamogon`.
- [ ] `flutter build ipa --release` на Mac; подпись через Xcode или `--export-options-plist`.
- [ ] TestFlight-сборка, затем ревью в App Store.
- [ ] Учесть: Apple строже всех к алкогольной тематике. Запасной путь — Android-платформы, iOS позже.

## Порядок действий (когда дойдём до M3)

1. Сгенерировать keystore, положить `key.properties`, настроить `signingConfigs`. **Ключ и пароли — в надёжное место, потеря = невозможность обновлять приложение в Google Play.**
2. Сделать иконку и сплэш, заменить дефолтные `ic_launcher`.
3. Собрать `.aab`, проверить подпись, загрузить в Google Play Console (внутреннее тестирование).
4. Собрать `.apk`, загрузить в RuStore (консоль разработчика).
5. Заполнить карточки: описание, скриншоты, категория («Образ жизни» / «Еда и напитки»), рейтинг 18+.
6. Дождаться ревью, исправить замечания (типичные: «пропаганда алкоголя» — снять формулировками, «нет политики конфиденциальности» — добавить ссылку).
7. iOS: после появления Mac/CI — TestFlight, потом App Store.

## Версионирование

- `VERSION` в корне — источник правды для документации и CHANGELOG.
- `pubspec.yaml` → `version: X.Y.Z+N`, где `N` — `versionCode`/`build number`. Оба должны совпадать с `VERSION` по X.Y.Z.
- Правило: перед каждой сборкой на публикацию — поднять `N`.

## Автоматизация (когда появится CI)

- GitHub Actions: `flutter analyze`, `flutter test`, `flutter build appbundle` на каждый пуш в `main`.
- Отдельный workflow для iOS: macOS-раннер, `flutter build ios --no-codesign`, проверка что код собирается под iOS.
- Секреты keystore — в GitHub Secrets, не в репозитории.

## Риски модерации

| Площадка | Отношение к тематике | Что делать |
|---|---|---|
| RuStore | лояльно к русскоязычным приложениям про хобби | рейтинг 18+, нейтральные формулировки |
| Google Play | политика по алкоголю: нельзя поощрять чрезмерное употребление и продажу | без продажи, без «как пить», акцент на учёт и рецепты |
| App Store | самые строгие; алкогольные приложения часто отклоняют | закладываем, но не блокируемся: iOS — второй приоритет |

Общий принцип: приложение — **журнал и планировщик**, а не руководство по употреблению. Это же и в описании в сторе.
