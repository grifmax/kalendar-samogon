# Правила работы над проектом

Проект: Android-приложение «Календарь самогонщика» на Flutter. Язык интерфейса, документации и коммитов — русский.

## Обязательный цикл изменения

1. Внести изменение (код, контент, документация).
2. Поднять `VERSION` по SemVer:
   - `MAJOR` — несовместимое изменение схемы БД или ломающий UX-передел;
   - `MINOR` — новая функциональность;
   - `PATCH` — исправления, тексты, документация.
3. Добавить запись в `CHANGELOG.md` (секция версии, дата, что и зачем).
4. Проверить:
   - `flutter analyze` — без новых ошибок;
   - `flutter test` — тесты зелёные;
   - миграции БД проверяются на чистой установке и на базе предыдущей версии.
5. Собрать APK (`flutter build apk --release`) — приложение должно ставиться и запускаться.
6. Коммит осмысленный, на русском: `feat:`, `fix:`, `docs:`, `chore:` + суть.

## Что не коммитим

- `build/`, `.dart_tool/`, `.gradle/`, `*.apk`, `*.aab`, `*.jks`, `key.properties`.
- Локальные БД, бэкапы пользователя, логи, временные файлы.
- Личные данные, реальные адреса устройств, пароли.

## Контент

- Рецепты и справочники — данные, а не код: хранятся в ассетах/БД и правятся без переписывания логики.
- Каждый рецепт имеет источник и пометку «проверен на практике».
- Чужие тексты не копируем: переписываем своими словами.
- Тематика алкоголя: без призывов к продаже, с рейтингом 18+, безопасность (метанол, огонь, вентиляция) — обязательный раздел.

## Архитектура

- Оффлайн-первый, без аккаунта и телеметрии.
- Слои: `data` (drift, репозитории) → `domain` (модели, расчёты) → `ui` (экраны, виджеты).
- Расчёты (калькуляторы) — чистые функции с тестами, без зависимости от UI.
- Любая новая зависимость — только с обоснованием в CHANGELOG.

## Тесты

- Калькуляторы — юнит-тесты обязательно (формулы проверяем на известных примерах).
- Генерация событий из рецепта — юнит-тесты на даты и повторяемость.
- Критичные сценарии — интеграционные тесты на БД (создание партии, миграция, бэкап/восстановление).
